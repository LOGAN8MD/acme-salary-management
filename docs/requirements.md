# ACME Salary Management — Requirements

**Version:** 1.0 · **Date:** 2026-09-28 · **Status:** Task 1 review draft

**Goal and user.** Give ACME’s HR manager a dependable web application to maintain annual base salaries for 10,000 employees across countries and answer basic compensation questions without managing spreadsheets. Success means finding an employee, safely changing a salary, tracing the change, and understanding salary distributions.

**Included scope.** One authenticated HR-manager role; an employee directory with name/code search, country/department/job-level filters, sorting, and server pagination; employee details showing annual base salary and currency; immediate salary updates with a mandatory reason; read-only change history showing old/new amounts, actor, and timestamp. The dashboard shows employee counts and total, average, and median annual base salary within a selected currency, with country, department, and level breakdowns. Directory and reporting filters use consistent definitions. All screens include loading, empty, success, and error states.

**Salary and reporting rules.** Annual base salary is a positive exact decimal, excluding variable compensation. Initial supported currencies are INR, USD, GBP, EUR (two decimal places), and JPY (zero); country and pay currency are separate fields. Currency cannot be changed through this version. Mixed currencies are never added or averaged. Salary changes and history are saved atomically; stale edits are rejected. Identical salary updates are rejected as no-ops. Initial seeded salary records are labeled separately from revisions. Reports describe pay distributions, not causes or conclusions about pay fairness.

**Deliberately excluded.** Payroll, taxes, payslips, bonuses, and benefits require rules beyond base-salary maintenance. Currency conversion is excluded to avoid misleading comparisons. Future-dated revisions, approvals, additional roles, and SSO add workflow complexity. Employee creation/deletion/profile editing and spreadsheet import/export are excluded to prioritize salary correctness; employee profiles come from synthetic seed data. A customer website and AI chatbot are unnecessary for the core HR journeys. These limitations make this an assessment application, not a replacement for a full HR information system.

**Technical and quality expectations.** Node.js/TypeScript API and React/TypeScript UI; proposed PostgreSQL with migrations. Use a reproducible seed script for exactly 10,000 employees. Protect salary data with authentication, validate inputs on the server, use precise money handling, and paginate in the database. Include fast deterministic unit tests, database integration tests for transactions/reporting, and an essential browser journey. Measure directory and reporting latency against the seeded dataset and document the environment and results.

**Acceptance and delivery.** Demonstrate login → employee search → salary update → matching history and refreshed reporting. Tests must verify invalid amounts, stale edits, atomic writes, and currency isolation. Deliver the deployed application with persistent data, repository and reproducible setup instructions, a short video demo, incremental commits, and evidence of actual AI usage and design trade-offs. Use only synthetic employee data. The recruiter’s `[X days]` deadline remains unconfirmed. Implementation proceeds one task at a time, each followed by user review and explicit approval of the next task.
